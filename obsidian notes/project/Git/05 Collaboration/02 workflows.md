**1. centralized workflow**
we have a remote repository on the GitHub, every team member and collaborator, clones it on their machine and then work with it, it's usually for private team

**2.integration manager**

this workflow is for the open-source projects, in this workflow, we have maintainers which have permission to push changes to remote repository, and we have contributors who wants to contribute to project because some people may apply malicious code on the projects, contributors don't have direct permission to push their commits on the projects, so the contributors first fork the project on their GitHub, then clone it on their machine and after that they can work on the project and push their commits to their forked version of project and then send a pull request to the maintainers which is basically telling them, hey, check my forked repository and if you think it's ok, pull it and push the changes into the main remote repository you have access to it.
