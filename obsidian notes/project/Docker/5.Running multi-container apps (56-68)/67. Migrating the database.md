command property in docker-compose file: It replaces the `CMD` instruction in the Dockerfile, we use it when we don't want to change the Dockerfile which subsequently requires anew image build.

in the command property, it's like we're running the CMD instruction from Dockerfile so when navigating to any path, navigate like you're in that service Dockerfile.

CMD cannot interpret the `&&`, so if your command has one of these you should use a shell file like `docker-entrypoint.sh` and link that shell file to command property and that shell file has access to `docker-compose.yml` file and can use the hosts.

in this video we were trying to migrate our database before starting our app, and migrating database requires database engine to run first which can take few seconds so we used `wait-for` third party command for it to verify the database engines runs first then we migrate our database.

## Database Migration = Changing Your Database Schema

**It's a way to update your database structure (tables, columns, indexes) without losing existing data.**

---

## Example

**You have a `users` table:**

| id  | name |
| --- | ---- |
| 1   | John |

**You need to add an `email` column:**

**Migration file:**

sql

ALTER TABLE users ADD COLUMN email VARCHAR(255);

**After migration:**

| id  | name | email |
| --- | ---- | ----- |
| 1   | John | NULL  |

**Data is preserved.**
