
when we run a docker-compose, docker creates a network with our containers as their hosts (consider each container as a machine or website), these containers connect each other and establish and execute our app, these containers can communicate with each other like a network.
but why we need such a network, when we have our front-end, back-end or database on our machine when developing them, all of them are in our machine and our machine is their superset network and they communicate with each other through our machine or when our application is in production and we upload to server, the backend and front-end server communicate with each other through internet, each container within or without a network is like a machine and has an IP (you can run the container and check it via `ifconfig`) and they're isolated, we should connect them through a network so we connect our back-end, front-end and database code together, so that's why use docker-compose file to create that network and different container connect with each other with their IP address and each container is like a machine or website or host with their service name is the host name or web address, like instead of typing localhost:3000, we just type frontend, this mean we can reference containers in other containers via their host name or use their hostname in our docker-compose file for like environment variable (address of a database), in other services, imagine you have run front-end container, if you type `ifconfing backend`, 
it test ping of the backend container like what we do for sites over internet.

so how does a container can detect other containers, docker has a DNS server which collects IP address of all of the hosts and their name (like DNS) and we have a DNS resolver in each container, so when we use a host name in our container, the DNS resolver of that container calls the DNS server and asks for IP of that container and then connects to that specific container.
