 as a developer we create our Dockerfile on each side of the application like the front-end, back-end and etc, when we merged the application and we have multiple Dockerfile it's time to create a Docker-compose file for composing these Dockerfiles, Docker-compose is like creating a super container and run and link all of the containers from different services and run our application. 

you can only use docker-compose command in a directory which the `docker-compose.yaml` exists and it's not like `docker` command itself. 

`docker-compose up`: it starts our application by running the images we have in different services and Dockerfiles, if you haven't build images via `docker-compose build`, it will build the images and pulls the images from dockerhub automatically and then run them and link them together to represent our application.

`docker-compose up -d`: it runs the container in detached mode.

when we run containers in detached mode, they will persist when we close the terminal and strangely if we run the containers in the foreground, they will still persist if we close the terminal and they become some sort of detached containers, the foreground containers only will be stopped if we press `CTRL+C` in the terminal.

`docker-compose down`: stops and **removes** all of the running containers in the background

`docker-compose ps`: shows all of the running containers of the specific application that has docker-compose while `docker ps` shows all of the running containers including those run by docker-compose.

`docker-compose ps -a`: shows all of the stopped and running containers
