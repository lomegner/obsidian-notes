Docker Compose is a tool that lets you define and run multiple containers (like a web app, database, and cache) together using a single YAML file and one command.

docker compose creates a superset container which includes all of the subset containers and connect them through a network.

when we're working as a front-end developer, we have our own Dockerfile, when we're working as the backend developer we have our own Dockerfile, then when project reaches a point we merge back-end and front-end together, we have to run a docker compose to have both containers and see how the application works and if we install any package and we faced a problem in our container we should check the problem on Dockerfile of each section like backend or front-end, `docker-compose.yml` is just for connecting all Dockerfile together. 

when we run our docker-compose, a networks gets created which services are its hosts.

an example of `docker-compose.yaml` file:
``` YAML
version: "3.8" #(the number should be wrapped in "", otherwise it won't work and there should a space between the name and value)

#version is for making a compatability betwen the docker compose and docker engine which is now depracated and docker uses it's latest version always regardless of presence of the version instruction.
  
services:
# services is for specyfing different part of the application and building and running their docker file.
  frontend:

    depends_on:

      - backend

    build: ./frontend #(this is the address to find this section of app Dockerfile)

    ports:

      - 3000:3000 #(ports to use when running this section container, EXPOSE instruction is useful here, we can check the port of this section from EXPOSE instruction of its dockerfile)

  backend:

    depends_on:

      - db

    build: ./backend

    ports:

      - 3001:3001

    environment: #(for defining the environment variables)

      DB_URL: mongodb://db/vidly

    command: ./docker-entrypoint.sh

  

  db:

    image: mongo:4.0-xenial #(for pulling an image from dockerhub)

    ports:

      - 27017:27017

    volumes: #(specifying a volume for our container)

      - vidly:/data/db

  

volumes: #(creating the volume)

  vidly:
```

## Arbitrary Values (Your Choice)

| Arbitrary Value              | Explanation                      |
| ---------------------------- | -------------------------------- |
| `frontend`                   | You named this service           |
| `backend`                    | You named this service           |
| `db`                         | You named this service           |
| `./frontend`                 | Path to your frontend Dockerfile |
| `3000:3000`                  | Your chosen port mapping         |
| `DB_URL: mongodb://db/vidly` | Your env variable name and value |
| `./docker-entrypoint.sh`     | Your script name                 |
| `mongo:4.0-xenial`           | Your chosen image                |
| `vidly`                      | Your named volume                |

## Built-in Docker Compose Keys (Reserved)

| Built-in Keys                | Purpose                   |
| ---------------------------- | ------------------------- |
| `version`                    | Compose file version      |
| `services`                   | Defines container section |
| `build`                      | Build from Dockerfile     |
| `ports`                      | Port mapping              |
| `depends_on`                 | Startup order             |
| `environment`                | Environment variables     |
| `command`                    | Override default command  |
| `image`                      | Docker image to use       |
| `volumes` (at service level) | Mount volumes             |
| `volumes` (top level)        | Define named volumes      |
please notice to indentation and always observe them for having a hierarchy.
