
`base image:` A base image is the starting point defined in the `FROM` instruction — it provides the operating system userland and/or runtime environment (like Node or Python) that your application needs to run, it will add basic files we need for our container which is operating system and package manger like node, in some cases if you add node as your base image, it contains linux operating system in it (it has linux because it's designed in this way), so we just type:

`FROM node:alpine20.3` 
and we have access to both alpine linux distribution and node package manager in our container.

never use this type of instruction:

`FROM node`
because it's equal to `FROM node:latest` and every time we have a newer version of a node, our application is built upon that which this logic is against concept of using docker, we want to have a specific version of a node but if installed a package which was unavailable in that version of node, we have to change the node version of docker image.

when we have `FROM node` in our image Dockerfile it means we can access to linux file and node package manager in our container and the container is not just for running the application.

for an image with a Dockerfile with
`FROM node`
if we run:

`docker run -it lome`(image name), it turns to a terminal (because of -it) which we access to node, like we can type stuff like `console.log("hi")` and it will return `hi` and if type:
`docker run -it lome bash`
it will run the linux bash or terminal we have in our container, basically using the bash or any command at the end of the `docker run` command will override the CMD instruction of our docker file which is responsible for running the commands by using a command at the end of the `docker run` command, every instruction in the Dockerfile will be executed except for the CMD and it will be overridden by the command we have used at the end of `docker run` command.

so `docker run -it lome bash` is an approach to use the linux operating system of our specific container and then we can run our code or application via that container ( all of the packages are installed and codes are copied already because they were not part of CMD instruction)

some linux distribution like alpine don't have bash and we to use shell, so type the code like below:

`docker run -it lome sh`

you can finds tags for your base images on the dockerhub.
