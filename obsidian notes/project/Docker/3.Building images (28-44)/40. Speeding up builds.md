
Docker creates a server-like environment on your machine so you catch and fix issues during development, then deploy to the real server with confidence that it will work immediately. so main application of docker is for deployment on the server to avoid any unknown issue while deploying on the server by creating a container instead manually installing packages and pulling code from GitHub which can cause lots issues like different node version required for application and node
version installed on the server or some other issues which I will supply in the rest of this article.
by using docker and creating a container, we can catch this issues during the development and when they haven't got that huge to resolve, so when we want to deploy our application it will be fast and without any stress.

so after we got added to a project and cloning the project, we install the packages via 
`npm install` on our machine and usually our node difference on the docker file and the machine won't make any problem since we usually have the higher node version on our machine but if we confronted an issue, we have to inform other team members to upgrade the node version on the Dockerfile, then after coding and checking it's result it's time to build a docker image out of it and see if it has problem or not like its node version may not support the most recent installed packages on our machine, so If we confronted any issue, we fix it and if we didn't it's a like test pass for our server and we do this till we finalize the application and want to deploy it finally, so we deploy our final docker image on the server, it would take like 2 minutes without any stress but without docker it would take like 1 hour (installing all of the packages and pulling codes from GitHub) with lots of problems that could occur.

for building everything faster on our machine each time we ended our coding and want to check it on the docker image also, we have a technique, like imagine you haven't installed any packages but you have for sure added some new lines of code, the docker engine has a process which checks if the instructions are changed or the COPY instruction files has changed or not and for sure `COPY . .` contains our code and our packages, so if these changes, it will rebuild the specific layer (each instruction is a layer) and its following layers in our image but if these don't change it will use its cache and things get done faster, so imagine you have added some new lines of code but you haven't added any packages, and you have:

```
COPY . .
RUN npm install
```

in this scenario since, `COPY . .` files has changed due to change in our codes and 
`RUN npm install`  is the following instruction, so the whole packages will be reinstalled again which is time consuming but if we change our Dockerfile to this:

```
COPY package.json .
RUN npm install
COPY . .
```
now the packages won't be installed since `COPY package.json .` hasn't changed and we have a faster build process.

and also change in order of instructions even adding empty lines will rebuild the the specific layer and it's following ones.

so always keep stable instruction like `FROM` on the top so they don't get rebuilt each time and keep the changing instruction at the bottom but bear in mind some instructions depends on each other, so don't force place of an instruction because of optimization at build.
