when we're server and a problem shows up or even we wonder what version of app had such an issue or even we need different version of an image for different environment including: server, test and etc. so we have to tag them, usually we tag them based on the build numbers that increment based on each build, you can use name like buster or a version like 3.1.5, in the development we don't need to specify tag for our built image but when we merge it on the master and we want to push it to dockerhub or server, there we have to specify the tag and reference the latest to the most recent created image so we know which image is the latest one.

when we build a new image without changing the file contents or instructions of the Dockerfile,
the newly built image will have the same image id as the previous one.

`docker image rm react-app:1` : for removing the react-app image with tag of 1.
`docker image tag react-app:latest react-app:1`: this command creates a new image same as `react-app:latest` and name it `react-app:1`, so both `react-app:1` and `react-app:latest` will share the same image ID, and if already there is an `react-app:1`, the newly created 
`react-app:1` will take its place.

the approach is we build an image with specific tag when we want to deploy to server:
`docker build -t react-app:2 .`

then reference the latest to this image:
`docker image tag react-app:2 react-app:latest` 
and push both of them to server for using them and we have specified which version is the latest.
