container is like an empty window or space, for working and running within that we need an OS, package, code.

an image includes everything an application needs to run or in other words is like zip file, it includes operating system, package manager, the code and ....

when we run `docker run lome(image name)`, it's like we're extracting that zip file inside the container, it installs the operating system, it installs the package manger, then copies the code and runs the code, imagine without a package manger and operating system how that code is going to get executed.

from now on whatever we install in that container only belongs to that specific container like applications we install on our machine and OS, when we check on our friends machine and computer, even though they have the same operating system, the don't have the same applications we have, so if you run the same image, it will in a new container without access to the file and packages we had in the previous containers.

so consider container like a virtual machine that needs everything to be installed on it including the OS, package manger, files and etc. and image is like a zip file which helps the container to have access to the things it needs to run the application.
