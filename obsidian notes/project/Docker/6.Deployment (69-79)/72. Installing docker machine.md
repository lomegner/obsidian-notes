this is how deployment works:

you find or purchase a server, it either has a GUI or the server company gives a username and password( second scenario is more common), in the first scenario you use an application or whatever the server company instruction is, in the second scenario, you use `ssh` command to connect to server, when you`ssh` to a server, it basically means you have sit behind that computer and using it i.e. it gives you access to another computer from your own computer. 

most servers with the windows as their OS, come with GUI (but always double check because some of them can be GUI-less) and usually the Linux servers are GUI-less.

if you want to deploy or run a application or a website, use Linux server which is cheaper and has lots of other benefits (I can't remember right now but you can ask) and If you want to use an website or application which is banned in your country and bypass the sanctions like paypal, you can use windows server since you need the GUI to access some software.

so after you logged into your server or VPS, you need to clone your code from GitHub to it and then you build your docker image and run it on the server, you give your server a domain name in the server configuration setting, and now you can run the app on that domain name.

I used `GitHub codespace` feature which first you need to create a repository on GitHub (there is no need to push anything in that Repository, it can be an empty repository), then it gives you a server with visual studio code on it and a terminal and connected to that repository you created earlier, in this environment you can run your application or use it as an environment for coding.

you can also install GitHub CLI to access your GitHub codespaces from your own machine:

GitHub CLI installation procedure:

``` 
download it from github.com/cli/cli

then check the app is installed.
check if it's installed on your machine via:

gh --version

then  for authorization use:

gh auth login -h github.com -s codespace

login into your account on github
then you can use

gh codespace ssh 

to ssh to your codespace and there is no need to supply any codeespace name in the command above since it shows all of the codespaces

gh codespace list
for listing codespaces
```
