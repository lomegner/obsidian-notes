
when we have different web server for our image like node.js and nginx we have to create different `Dockerfile` for each of them to catch errors of different environment based on each web server which this only happens in front-end side, we do this to see if any error we confront is related to which web server and if we put web servers with each other, it can cause confusion.

as I told you before, nginx has problem with anther user than root, so we deleted the app user instruction from our `Dockerfile.prod` in our frontend, this is one of the errors we found in our production `Dockerfile`, if we had one `Dockerfile` we couldn't discover which web server has problem with normal user but since node.js works fine with normal user, I realized that nginx has problem with it, this is one of the issues we can resolve before deploying to server and causing a boilerplate.

another thing is we had created a shell file for database migration called `docker-entrypoint.sh`, docker doesn't run this file hence our backend doesn't run, so instead of using that shell file, just add those commands directly to your CMD command via:

```
CMD sh -c "echo 'Waiting for MongoDB to start...' && ./wait-for db:27017 && echo 'Migrating the database...' && npm run db:up && echo 'Starting the server...' && npm start"
```
since `&&` cannot be comprehend via CMD itself we need to use `sh -c "command"` after CMD.
