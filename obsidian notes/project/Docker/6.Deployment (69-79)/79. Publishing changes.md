
when you create images on your server, later you push new features to code and you want to create their images also, that's why we give our images tags and we only keep 1 or 2 images ago from the latest commit, so we can roll back to those images if anything went wrong and we remove the older images to prevent making our server bloated.

image: vidly_frontend:1 (that specific service image:tag)

we add this property to a service to create an tagged image of its image, that's why we should use a currently built image name.

anytime we want to create anew image in our server we have to increment its build number in image while if we knew CI/CD  it could've been done automatically.

`docker-compose.prod.yaml` file:

```
version: "3.8"

services:
  frontend-prod:
    build:
      context: ./frontend
      dockerfile: Dockerfile.prod
    image: hi-new_frontend-prod:1  
    ports:
      - 80:80
    restart: unless-stopped

  backend:
    build: ./backend
    image: hi-new_backend-prod:1 
    ports:
      - 3001:3001
    environment:
     DB_URL: mongodb://db/vidly
    restart: unless-stopped

  db:
   image: mongo:4.0-xenial
   ports:
     - 27017:27017
   volumes:
     - vidly:/data/db
   restart: unless-stopped  

volumes:
  vidly:
```

as you can see the value after image is the name of the image built by `build` property.

we also tag the latest tag of that specific image to the most recently created tagged version of that image to be able to keep track of that latest tag.
