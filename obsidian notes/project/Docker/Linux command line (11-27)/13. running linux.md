for running a docker command (any commands that include word `docker` in it), the docker desktop should be running in the background, so before typing any docker command in your terminal, make sure you have clicked the docker desktop already.

`docker image ls` = shows a list of images on your machine

docker build -t lome (image tag name) . (address where to find dockerfile which . implies to current directory in this case)= building an image

docker run lome (image name)= runs the specific image 

docker run -it lome(image name)= runs the specific image interactively, some images like ubuntu which we may need their terminal and we need to interact with them we have to run them interactively but if we need just a result to be displayed, `docker run` should be enough.

history= shows a history of commands we've executed 
!2 (number)=executes the command with number of 2 in the history list

`#`= represent the root user for the normal user we have `$`.
root@number=/# :first part before @ is the current user and the number represents the machine which is like name of the machine. `/` represent the root directory in the machine and we spoke earlier about `#`.

linux commands are case-sensitive.

we can run images from anywhere on our machine

images are a lightweight app which we download them and we can run them whenever we want which they don't have any specific difference in performance with the actual installed file.

for pulling (download) an image we can type `docker pull ubuntu`(image name which can be find on docker hub) but this approach only pulls this and doesn't run it, if you haven't pulled this image yet, you can type docker run ubuntu, which firsts check the local directory to see if it finds that specific image to run it, if it doesn't finds it, it first pulls it from docker hub and then runs the image.

image in development are about ease of use not size because the team member when creates the image it's the same size of when it downloads the packages directly but in docker it doesn't need to know to download which packages and docker take charge of this but when we clone a repository and now want to code, we should check the `package.json` to download necessary packages and this action is cumbersome or sometimes we have installed a package globally but a project needs a specific version of that package (like node), so by using docker, each container runs images with specific version of that package, furthermore you can easily delete the image and subsequently the packages but in a project it may be difficult to delete and delete a package.

and in application use of docker, for example in ubuntu, we want to run a script in Linux environment, we don't need to download linux and install it, we can pull the image from docker hub but this image has basic features and not the gui tools like a browser but it satisfies our needs and that's why it's lighter than the actual linux, so we can use this image which is easier to install and lighter and easier to uninstall and after uninstall no trace will be remained unlike the traditional installation.
