docker is a platform for making our applications easier to use among the team.

it creates an image of our application with all of the code, dependencies and packages inside that, so when a new team member tries to work with our application and develop it, they don't spend multiple of hours to download the packages they don't need to pollute and make a clutter on their machine and easily let docker to run those packages and code on their machine.

they may still require some packages for development like for autocompletion of the syntax, so the installation of those packages is not an obstacle and always the most recent version of the app takes place in the `package.json`.

the backbone structure of docker containers are linux, since we can run containers with linux as their kernel on all of the operating systems.

image is a like a zip file with our code files, their packages and dependencies in it.

container is a place you put that image in it and it runs image inside of it on other people computer.

image is a like precooked food, it's a file containing our codes, installed packages and you need to run it on your device to access that application temporarily.

2 applications of docker image is first as a user, for running an application on your machine temporarily without any need to install it and allocate some of your storage to its data like using Ubuntu or MySQL, the second application as a developer, we dockrize our code with a dockerfile, so when the other team member clone repository, they can work on the project without requiring to install lots of unnecessary packages.

we have a docker hub which is basically like GitHub, you can push (upload) images to it and other people can pull it to use it, like for the first application we literally pull the images from dockerhub like ubuntu but this docker hub is not useful as a developer, because we push our code on `github`
alongside the `Dockerfile` and docker image creation instruction and the other team member easily creates an image with `docker build -t` and they can run that image to see what they have made on the application but if we push our application image on dockerhub, they don't have access to code and they have only have access to final application and image, it can be only useful for publishing the final application so may other people want to use our application.
